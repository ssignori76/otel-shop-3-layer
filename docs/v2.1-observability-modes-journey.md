## Architecture Decision Records (ADR)

- **ADR-01 (Unified 3-Mode Symmetry)**: Both Docker Compose and Kubernetes expose the exact same 3 operating modes: `dev` (local observability stack), `prod` (Dynatrace OneAgent, all OTel exporters OFF), and `prod-otel` (official Dynatrace OTel Collector).
- **ADR-02 (Full Observability Parity in `dev`)**: Docker Compose `dev` (`compose.dev.yaml`) now includes **VictoriaMetrics** (`:18428`) and **VictoriaLogs** (`:19428`) alongside **Jaeger** (`:16686`), matching Kubernetes `dev` (`k8s/overlays/dev`) 1-to-1.
- **ADR-03 (Official Dynatrace OTel Collector + Grail Delta Counters)**: Mode 3 (`prod-otel`) uses the pinned official `ghcr.io/dynatrace/dynatrace-otel-collector/dynatrace-otel-collector` image with `cumulativetodelta` (`max_staleness: 25h`) on the `metrics` pipeline (plus `OTEL_EXPORTER_OTLP_METRICS_TEMPORALITY_PREFERENCE=delta` on Java services) so counter metrics ingest cleanly into Dynatrace Grail.
- **ADR-04 (Dual Token Scheme Support)**: `prod-otel` supports both classic Dynatrace API tokens (`DT_AUTH_SCHEME=Api-Token`) and Platform Tokens (`DT_AUTH_SCHEME=Bearer`) via environment variables / Kubernetes Secret with explicit inline comments.
- **ADR-05 (Always-On Cloud-Native `stdout` JSON Logs)**: Container `stdout` JSON logging remains unconditionally active in all 3 modes — including `prod` when `JAVA_TOOL_OPTIONS=""` and `OTEL_*_EXPORTER=none`.
